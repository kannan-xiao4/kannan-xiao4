## IRIAM｜2025年9月〜現在

### 役割

2025年9月にクライアントエンジニアとして入社。同年11月から機能開発のリード・プロジェクトマネジメント（PjM）、2026年1月からグループリーダーとしてチーム運営を担っています。

### クライアント開発・プロジェクト推進

- アプリ内ホーム画面など、配信外領域のUI・機能開発。
- 機能開発からリリースまでのプロジェクト推進と、開発・リリースの調整。
- 複数の開発ラインを運営するためのチーム設計と、役割・期待値の整理。

### チームマネジメント・育成

- 主管チーム全体のピープルマネジメント。
- 直接評価者としてのメンバー評価、評価会での説明、本人へのフィードバック。
- 目標・役割設計、1on1、新卒・若手のメンタリング、課題解決の相談対応。
- 後任リーダーへの期待設定と、段階的な引継ぎ・権限移譲。
- プロジェクト管理の委任と、中長期の課題を見据えたチーム体制の検討。

自身が開発を進めることに加え、メンバーが判断・実行できる状態をつくることに取り組んでいます。個々のメンバーへの支援と、チーム全体の役割・責任・期待値をそろえることの両方を担っています。

## ソフトギア｜2023年9月〜2025年8月

### 役割

リードソフトウェアエンジニアとして、メタバースサービス「neem」の開発を担当しました。2024年8月から製品開発部長、2025年2月から開発本部副本部長を務めました。Unityクライアント、WebRTC、APIサーバー、Webフロントエンド、GCPを横断し、機能開発から既存システムの改修、リリース・運用整備まで取り組みました。

### 主な実績

- **開発・運用の内製化**：外部委託していた開発・インフラ領域の内製化を推進し、社内で開発・運用できる体制を整備しました。モバイル配布CIの構築はメンバーに委任し、インフラ面を支援。Windowsアプリの署名も自動化しました。
- **モバイル版のリリースとPC・モバイルの実装統合**：主要機能の実装をメンバーに任せつつ、WebRTCのビルド・動作不良、AndroidのVulkan処理、シーン遷移時のリソース解放漏れ、テクスチャの重複使用などに対応しました。その後、サービスロケーターを用いた構造へPC・モバイルの実装を段階的に統合し、互換性と端末ごとの操作体験を考慮して移行しました。
- **既存ユーザーデータを引き継ぐVRM化と性能改善**：同梱アバターから外部VRMへの移行に際し、読み込みの基本実装をメンバーに委任。自身は旧マスターを参照する着せ替え情報の移行・検証、複数体表示とメモリ負荷への対応を担当しました。リリース後にはVRMライブラリ内の処理を並列化し、要求を満たす読み込み速度に改善しました。
- **決済接続基盤と月次課金の検証・運用**：決済APIの接続元IP制限に対応するため、Kubernetes外のプロキシを経由する通信経路を構築・検証しました。月次課金では予信から翌月の売上確定、決済失敗時の利用制限までの状態の整合性をQAと検証し、リリース後も毎月の処理状況を確認しました。
- **サービス全体の負荷試験とデータ移行の仕組み化**：リアルタイム同期・WebRTC・APIを通した負荷試験用BOTを実装し、GCPのスポットVM・コンテナ・Cloud Armor・Jenkinsを使った実行環境を構築しました。環境間のマスターデータ・関連ファイル移行では手順を確立し、QAメンバーへのシェル化の委任とJenkinsへの組み込みを行いました。

### その他の開発・推進

- 配信機能を汎用化し、ゲストマイクと複数配信者からの受信に対応。再生同期・画面共有はメンバーによる実装を支援しました。
- 開発計画、チケット・リリース管理、経営層・営業・法務との要件調整、開発工数やインフラ費用の見積もりを担当しました。

単一の機能だけでなく、既存データとの互換性、性能、検証可能性、リリース後の運用まで含めて課題を解決することを重視しました。また、自身で手順や実装方針を確立した後にメンバーへ委任し、継続して扱える仕組みにすることにも取り組みました。

**主な技術**：Unity、C#、C++、WebRTC、Kotlin / Spring Boot / R2DBC、TypeScript / SvelteKit、PostgreSQL、GCP / GKE、Terraform、Helmfile、Jenkins。

- Unity Profilerとの統合によるパフォーマンス計測への対応。
